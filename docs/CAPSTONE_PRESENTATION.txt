🎙️ PRESENTER SCRIPT (Josepito Quezada — Target: 0:50)
"For our system analysis and design methodology, we adopted the Rapid Application Development—or RAD—framework. RAD was selected because its four iterative phases—Requirements Planning, User Design Prototyping, Construction, and Cutover—enabled us to rapidly build functional prototypes and refine them based on actual library workflows. Architecturally, we structured the software into four distinct tiers: A reactive Presentation Tier powered by NiceGUI and Vue 3; An AI Cognitive Tier hosting local Llama 3.2 3B and ChromaDB vector search; A Core Services Tier managing role-based access control, institutional form exports, and business logic; And an asynchronous Persistence Tier backed by MongoDB Motor. This separation guarantees modularity, sub-second response times, and effortless future extensibility."

- Logistics Scope: Attendance automates digital gate logs; it does not control physical motorized turnstiles.

DEFENSE PANEL Q&A QUICK REFERENCE GUIDE
================================================================================
Q1: "Why use local Llama 3.2 instead of ChatGPT or Claude API?"
Answer: "Commercial cloud APIs require sending student research drafts to overseas cloud databases, violating data sovereignty under the Philippine Data Privacy Act of 2012 (RA 10173). Local execution guarantees 100% data sovereignty, eliminates recurring monthly dollar subscription fees, and functions reliably during campus internet outages."

Q2: "How does the system comply with copyright laws (RA 8293) if documents are digitized?"
Answer: "We enforce institutional read-only DRM. Students and guest users can read documents in-browser with persistent progress tracking, but cannot download raw source files. The download button is restricted by role guards strictly to authorized librarians and administrators."

Q3: "How does Libre-Library improve upon NEMSU's existing Follett Destiny OPAC?"
Answer: "Destiny OPAC indexes only basic bibliographic metadata like author, title, and call number. If a student searches for a concept discussed inside Chapter 5 of a textbook, Destiny returns zero hits. Libre-Library vectors full document text into ChromaDB, enabling semantic natural language search and conversational Q&A with exact page citation chips."

Q4: "How does the QR gate prevent doorway bottlenecks during peak morning hours?"
Answer: "Our QR scan engine runs asynchronously with MongoDB Motor non-blocking queries, recording check-ins in under 0.2 seconds (< 200ms). This eliminates the 30-second pen-and-paper signature delay at the door."

Q5: "How does the system support institutional ISO 9001:2015 library standards?"
Answer: "We implemented exact digital schemas for standard forms: FM-LIBS-009 (Library User's Logbook Form) capturing student ID, year level, purpose, and dwell time, and FM-LIBS-002 (Book Request Form) capturing publisher, copyright year, unit price, copies, and total procurement budget, both exportable to official CSV format."

Q6: "What is your testing methodology and test coverage?"
Answer: "We execute 74 automated unit and integration tests covering RBAC permissions, Bcrypt hashing, JWT expiration, LRU caching, QR scan throughput, FM-LIBS-009/002 exports, and RAG vector retrieval, running cleanly in 21.6 seconds."

Q7: "What happens if the local AI server hardware is low-spec or lacks a dedicated GPU?"
Answer: "We utilize quantized 4-bit (Q4_K_M) Qwen 2.5 3B GGUF model weights running offline via llama-cpp-python with 100% CUDA GPU offloading (e.g. RTX 3050 Laptop GPU) and graceful CPU fallback. The quantized model consumes only ~1.96GB of storage and runs with ultra-fast 3–5 second token latency (~25 tokens/sec)."
